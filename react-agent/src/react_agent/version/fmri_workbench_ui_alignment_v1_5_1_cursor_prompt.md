## 3. 统一栅格、视觉基线和响应式

先建立或整理页面 layout tokens，再修改三页。下列数值为 CSS 像素建议；若仓库已有 tokens，应复用并调整到相近结构。

~~~css
:root {
  --header-h: 60px;
  --sidebar-w: 264px;
  --content-max: 1560px;
  --page-x: 24px;
  --section-gap: 20px;
  --panel-padding: 24px;
  --control-h: 36px;
  --radius-panel: 10px;
}
~~~

实施标准：

1. 顶部栏、侧栏和主内容的垂直边界严格对齐；主区标签页、样本标题卡、摘要卡、下方左右分栏共享同一左右边线。
2. 主区有最大宽度；在很宽的屏幕上不要让一行协议或表格从屏幕一端横跨到另一端。脑图页可使用更宽的分析容器，但要明确使用同一间距系统。
3. 卡片使用统一边框/圆角、标题样式和内边距；禁用每个页面临时不同的 22px、25px、31px padding。
4. 使用 8px 间距基准：常见间距 8、12、16、24、32；状态徽标与文字之间、按钮之间和表格行内都保持一致。
5. 页面标题、次级说明、数值、辅助注释建立稳定字号层次；不要到处都是差不多粗的 20px 字。
6. 表格数字右对齐且使用 tabular numerals；状态标签有固定的对齐列，不让长汉字使整列跳动。
7. 1280px 以下四张摘要卡自动 2×2；窄屏一列。脑图三视图适度变为 2+1 或单列，维持脑表面纵横比。
8. 侧栏和内容必须设置 min-width:0 / min-height:0 等必要布局限制；不要用 overflow:hidden 掩盖内容错位。
9. 保留主内容一个主要纵向滚动区；侧栏列表允许独立滚动，但尾部控件不得覆盖最后一条记录。
10. 颜色继续克制，延续现有蓝色选中态与白色卡片；不要加新的渐变背景或大面积阴影。

建议的 CSS Grid 关系是：桌面左栏固定宽、主区 minmax(0,1fr)；主区内内容居中并有 max-width；摘要区 repeat(4,minmax(0,1fr))，中等宽度 repeat(2,1fr)。采用现有布局体系表达同样关系即可，不强制某一框架。

## 4. 顶栏和侧栏

顶栏只承担全局导航与当前运行状态：

- 左侧显示“fMRI 检查工作台”；当前样本放较轻的面包屑或仅在内容页大标题显示，避免并排两次强强调 antenna_01b。
- 右侧保留运行状态、新建检查；数值检查结论以概览卡为主要呈现位置，顶栏只在确有必要时保留短标签。
- “运行完成”与“配置内检查通过”含义不同，颜色、文字和 tooltip 要清楚，不把它们合成一个质量分。
- 顶栏按钮中心线、徽标基线对齐；新建按钮的高度与其他控件统一。

侧栏把同一 sample_id 的多个 run 按真实身份整理：

- 搜索框提示用“搜索样本或运行 ID”，不要直接展示内部字段名 sample_id。
- 推荐按 sample_id 分组，组标题显示样本名、运行次数；组内按实际时间降序显示不同 run 的时间、检查模式和状态。
- 若不改成分组，也要让同名运行的差别一眼可见，不能连排多个完全同名同状态的大卡片。
- 真正的唯一标识仍是 run_id + sample_id，点击某条历史运行必须打开那条运行；分组不能把结果合并。
- 若当前只有文件修改时间，就写“文件修改时间”，不能改成“检查时间”或“创建时间”。
- 列表项建议：首行样本名 + 简短状态图标/短标签；次行时间 + 模式。长“配置内数值检查通过”写在详情；列表用“配置内通过”且 tooltip 说明范围，避免小徽标折成两行。
- 选中项用浅蓝底 + 左侧或整卡细边线，不要同时叠多个蓝边/蓝底/粗按钮。
- 修复截图底部“显示菜单”字样与列表裁切：确认元素归属和滚动容器关系；最后一个 run 能完整滚动到视口内。
- 列表上限若实际有限，提供“更多运行”的明确入口；不要在 UI 里静默丢旧记录。

## 5. 概览首屏：压缩重复、强化层级

把大段协议说明改成紧凑元信息，用户第一眼看见：

- 样本名；
- 刺激图像缩略图（只有真实资源可用时显示）；
- 模式和时间轴的一句摘要，例如“16s · 4s 灰 / 1s 图 / 后续灰 · fsaverage5”；
- 输出形状“16 × 20,484”；
- 结论适用范围的一句话。

精确的 10 fps、segments、t_stim=t_video−4、LH||RH、checkpoint、是否额外平移、analysis_goal 等放进可展开的“实验与生成信息”。禁止前端写死图像 1s 或 16s；字段从所选 run metadata 获取，旧 12s 显示真实协议。

显示“数值一致性检查已覆盖当前配置的问题。真实脑响应未评估。”这样的范围句时，依据当前真实 run 的 coverage 和 claim_scope 选择文案；不要套用固定句子。

四张摘要卡对齐设计：

| 卡 | 主标题 | 主要值 | 副说明 |
| --- | --- | --- | --- |
| 1 | 数值检查 | 配置内通过 / 发现需关注项 / 暂无法判断 | 限定在当前配置与 claim_scope |
| 2 | 问题覆盖 | 5/5 之类的真实数 | 必需问题已回答；详情链接 |
| 3 | 检查深度 | L1 或实际达到的层级 | 实际执行的工具数 |
| 4 | 调用成本 | 1 次 / 0 次真实 LLM 调用 | 费用未知显示“费用未提供” |

同一组卡的主值从相同垂直基线开始；标签高度、副说明位置、卡高统一。主值不能把 0 和 null 混为一谈；截图中 1 次 LLM 调用若实际是已接受计划与 repair 混合，查看 Agent 轨迹时必须可区分。

不再在卡片下方用长句重复一遍卡片的结论。这个位置改成：

- 有需要关注的 followup/blocked → 简短提示与查看入口；
- 无未解决问题 → 一行中性的完成摘要；
- 没有新信息 → 省略该区域。

两栏主区让脑图预览占更大比重，问题覆盖更紧凑。大屏建议 3:2 或约 60%:40%；两张卡顶部对齐，底部可不强迫等高，避免脑图无意义留白。

问题覆盖：将内部 question_id 映射为人能看懂的名称：

| 原始 ID | 中文标签 |
| --- | --- |
| input_contract | 输入格式 |
| gray_comparability | 灰屏对照 |
| stimulus_temporal_description | 刺激时序 |
| coarse_spatial_description | 皮层空间分布 |
| triggered_followups | 后续检查 |
| reference_quality | 参考质量评估 |

行内只显示人类可读标签和状态。内部 ID、evidence_id 和工具来源放展开详情。“必需/可选”可用列标题或分组表示，避免每一行重复“必答”。

triggered_followups：确实没有 ticket 时显示“无待跟进问题”；有 N 个已解决时显示“N 项已完成”。不能单纯根据“answered”推断零个 ticket；看实际 ledger/ticket 数据。

reference_quality 按 report 的 required 字段显示。非必需且 unassessed 就中性“未评估”；如果是必需但未评估，显示实际阻塞原因。

## 6. 脑图与时序：工具栏、视图和时间轴

### 6.1 整理操作区

将当前散排的一排按钮分成三组，组间 16–24px：

1. 左侧：信号模式选择（contrast/raw/gray，按可用资源）。
2. 中间：上一帧、播放/暂停、下一帧；按钮高度一致。允许图标配短字，但别每个按钮都占 100px。
3. 右侧：适应窗口、全屏、全部帧视图；低频操作可做二级菜单，保留键盘可访问和 title/aria-label。

用一个小型 segmented control 切换“单帧 / 全部帧”，比独立的“全部帧”大按钮更明确。禁用状态必须和实际资源一致。

当前帧的一行显示“第 9/16 帧（索引 8）· 视频 8s · 刺激后 4s · contrast”这类明确区分自然数序号与从零开始索引的文案。视角 left/right/posterior 不应挤在此行，应贴在各自视图顶部。真实时间来自 manifest/segments。

### 6.2 脑图对齐

三个视图各放在等宽容器中；标签位置、留白、显示基线一致。图片 object-fit:contain，保留解剖纵横比。

跨帧默认保持每个视图的固定图像框、固定相机位置与固定显示比例；若既有 renderer 导出图的裁切/摄像机不同，优先在已有渲染输出修正；不要通过 CSS 强行拉伸大脑。

真实视角名称以 renderer metadata 为准。当前 screenshot 的 left/right/posterior 不得擅自翻成“LH lateral/RH lateral”，除非确实与 renderer 一致。

概览里的同一帧预览重用单帧数据和色阶；概览与脑图 tab 切换时，当前 frame/signal mode 同步或明显提示为何被重置。

### 6.3 色阶解释变得清楚

移除页面中英文重复的 signed 色阶文字；保留一份靠近脑图的紧凑色条：

蓝色端数值 → 0 → 红色端数值，旁边注明“模型输出单位”。

另加短句：“红/蓝表示当前可视化值的正/负，不代表脑响应已验证。”

准确数值限值来自实际 color metadata；截图的 −0.158、0、0.158 只是这条 run 的例子。不同 signal mode 的色阶变化需显示，不允许用户以为颜色强弱可以直接跨模式比较。单模式跨帧保持固定色阶。

### 6.4 时间轴

滑块与当前时间值上下紧邻，明确建立联系：

- 可见第 0…15 帧的实际采样点；
- 区分刺激前 gray、image 和刺激后 gray；
- 从当前 run 的事件时间读出 onset/offset，给出 t=4s、t=5s 标记；不同 profile 使用自身真实值；
- 当前帧高亮位置与脑图同步，键盘左右箭头可切换；
- 图像阶段只占 1s，允许画成窄区域，不放大成与 11s 灰屏等宽；
- 第 16s 是窗口终点，不伪造第 17 个采样点；
- “绝对时间 / 相对刺激时间”是坐标标签切换，不能偷偷移动或插值数据。

若下半页已有真正的时序曲线，把它与帧滑块共享时间位置；用户点击曲线的某个实际样本能跳到对应脑图。无逐帧序列时显示真实缺失原因，不生成平滑假曲线。

## 7. 指标解释：从长表改为可浏览的分组

将目前唯一的大表至少分成：

1. 输入与格式；
2. 分布统计；
3. 灰屏对照；
4. 时序特征；
5. 空间特征；
6. 模型和参考评估；
7. 运行成本。

只渲染此 run 实际有的数据。缺组显示“本次未执行/资源不足及其真实原因”或折叠，不用空图表占位。

顶端有组导航或锚点；默认展开用户最关心的“灰屏对照”“时序特征”及有有效 finding 的组。其他组可折叠，但 URL/浏览器回退应尽量保留位置。

表格布局：

- 列：指标名称 / 当前值 / 单位或状态 / 详情图标；
- 指标名称左对齐，数值右对齐，状态中性标签；
- 行高约 44–52px；长说明只在悬停、聚焦或详情显示；
- 去掉每行重复的完整“查看解释”按钮，保留统一的 info 图标；点击整行也可打开解释面板；
- 整行可交互要支持键盘 Enter/Space、可见 focus ring、aria-label；
- 表头与数字列始终对齐，避免每一组自己算不同宽度。

数值格式集中管理：

- mean 的 -0.00661015 等保留原始精度在详情中；表格使用适合的有效数字，例如 -0.00661；
- finite_ratio=1 显示“100%”；其数据字典注明输入为 0–1 比例；
- std/min/max 与原始数值单位保持一致，不能百分比化；
- 零显示 0，不显示短横线；null 显示“未提供”；
- ratio 若本身是“倍数”则写“×”，不能机械地乘 100 加 %；
- 千分位处理 20,484 等计数，帧数保持整数；
- 不因正数/负数直接上红或绿颜色。

结构化值要有摘要：

- shape = [16,20484] → “16 个时间点 × 20,484 个顶点”；
- quantiles → “P5 / 中位数 / P95” 真实数值；
- windows → 各阶段名称与时长；
- provenance → 信号模式、算法版本、输入来源；
- 多次 execution → 单独展开具体执行，不以 tool_id 覆盖。

一律用实际 JSON 数据判断字段存在性。数组缺长度或不能识别的对象，显示“查看原始字段”，不能用空摘要误导。

解释抽屉只打开一个，标题含指标名称和当前值；内部继续保留 V1.5 的“是什么/怎么算/能说明/不能说明/阈值来源/工具来源”。返回后焦点回到对应表行。

## 8. Agent 轨迹与其他 tab 的视觉一致性

本次主要修改上述三页。但顶部 tab 样式、内容容器宽度、分组标题、按钮尺寸、状态颜色，应同步应用到 Agent 轨迹和产物与记忆，避免打开其他 tab 突然变成另一套设计。
